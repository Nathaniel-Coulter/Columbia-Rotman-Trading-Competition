## COMP-2.0 decisions

- **Live default:** calibrated 100%-immediate-booking-gated SOR burst, unchanged threshold 5¢.
- **Research extension:** conditional core+tail for 5–under-10¢ edges, tested offline and behind two additional live opt-ins.
- **Gates:** core orders must be completely filled/reported and mirrored inventory confirmed before the tail clock starts.
- **Tail exits:** holding deadline, exposure mismatch, fine increase, end-of-round, stale/insufficient book, or configured edge stop/take. Every exit returns through full-order reconciliation.
- **Next prerequisite before relying on live tail:** one controlled demo execution and audit of partial-fill, venue, position, and accounting behavior.

## Evidence limitations

Only eight heats from one session were studied; conditions are not independent; participant order behavior changes; fees/tender semantics can change on competition day; mock server tests verify software logic but not live simulator fill kinetics.

## Market-data and fragmentation checks

Across this eight-heat archive, the data plane logged **98,139 full L2 book snapshots, 195,794 per-side participant feature observations, 5,873 TAS prints, and 235,843 HTTP samples**. RIT book GET latency was **1.64 ms median, 3.65 ms p95, 6.06 ms p99**, with **zero HTTP 429 responses**.

Among **32,564** Main/Alternative book observations paired within **20 ms**, **10,512 (32.3%)** showed a strictly crossed inter-venue best bid/ask. These observations are not atomic; a crossed quote is not proof an independent arbitrage trade could be executed or permitted. COMP-2.0 therefore does **not** add flat-to-flat cross-venue speculative arbitrage.

Participant quote shares were often zero at any instant, but participant orders appeared in roughly 18–33% of side/venue snapshots. The observed median age of currently visible participant orders was approximately 1.2–1.8 seconds versus ANON's ~48–60 seconds. This is a **visible-age statistic, not a true survival-time estimate**, and it remains telemetry rather than a hard-coded trader-ID rule.
