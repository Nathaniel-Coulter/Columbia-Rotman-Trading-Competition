The preflight checks:

- 2c market fee if exposed by server
- max order sizes are not below validated 25k/10k slices
- API order-rate metadata when available
- risk limits are not below the strategy's 100k net / 250k gross assumptions
- both strategy positions are flat
- no actionable/open orders already exist
- current fine baseline
- only one competition engine process can hold the lock

5) LIVE CLASS RUN
-----------------
python .\columbia\lt3_competition_engine.py --live-class

Normal class run: DO NOT add --research-logging.

6) Stop
-------
Press Ctrl+C once for a graceful stop. If a hedge is active, the script finishes
its accepted-tender hedge/verification path before exiting.

SAFETY BEHAVIOR
---------------
The script intentionally stops rather than guessing if it detects:
- a new RIT fine
- accepted tender inventory that cannot be reconciled safely
- residual position after hedge
- unfilled hedge orders
- material fee/P&L-model drift
- dirty inventory or open orders at startup
- wrong/missing LT3 tickers
- a case fee/max-order/risk configuration that is less permissive than the
  validated assumptions
- another copy of the bot already running

RIT CLIENT RESTART / CRASH
--------------------------
If RIT crashes while the Python process remains alive, idempotent GET requests
wait for the Client to recover. Unsafe POST requests are never blindly replayed.

If you must restart Python too:
1. Restart RIT and reconnect to the case.
2. Inspect that CRZY/TAME are flat and there are no live/partial orders.
3. Run --preflight again.
4. Only if PREFLIGHT: PASS, restart with --live-class.

Do not use an emergency/manual flatten merely because the scoreboard reset after
a Client crash; the competition engine treats actual security positions/order
state as authoritative.
